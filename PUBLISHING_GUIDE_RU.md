# Как добавить Showcase Kit в репозиторий ChemAnalyzer

Этот архив — **комплект файлов оформления и документации**, а не полный исходный код приложения. Основной исходный проект находится в `ChemAnalyzer_3.2.0_AntidotePrediction(1).zip`, который ты присылал ранее.

## Что входит в комплект

- `README.md` — новая английская главная страница репозитория;
- `assets/banner.svg` — баннер Dark Tech;
- `.gitignore` — правила исключения окружений, секретов и локальных данных;
- `COPYRIGHT.md` — режим публичной демонстрации без открытой лицензии;
- `docs/INSTALLATION.md` — инструкции запуска и сборки;
- `docs/ARCHITECTURE.md` — устройство приложения и API;
- `docs/ROADMAP.md` — план дальнейшей разработки.

## 1. Собери локальную папку проекта

1. Распакуй `ChemAnalyzer_3.2.0_AntidotePrediction(1).zip` в отдельную папку. Внутри будет каталог `ChemAnalyzer_Modern`.
2. Переименуй `ChemAnalyzer_Modern` в `ChemAnalyzer` (не обязательно, но так удобнее).
3. Распакуй этот Showcase Kit во временную папку.
4. Скопируй содержимое Showcase Kit поверх папки проекта, сохраняя каталоги. Разреши заменить старые `README.md` и `.gitignore`.
5. Не удаляй исходные `CHANGES.md`, `DESKTOP_BUILD_GUIDE.md`, `LICENSE_NOTICES.md`, `.github/workflows/build-windows.yml`, исходники `backend/`, `frontend/`, `electron/`, `scripts/` и файлы `.env.example`.

## 2. Перед отправкой проверь файлы

- Убедись, что `backend/.env` и любые другие реальные `.env` отсутствуют.
- Не добавляй API-ключи, пароли, сертификаты подписи, токены, личные данные и приватные логи.
- Не загружай `backend/models/`, `backend/training/data/`, приватные CSV и обученные модели без проверки происхождения, прав на данные и назначения.
- Пустые шаблоны в `backend/training/specialized_data/` можно сохранить: они уже являются частью исходного проекта.
- Сохрани `LICENSE_NOTICES.md`: в нём указаны сторонние компоненты и источники данных.

`.gitignore` помогает исключить такие файлы, но не заменяет ручную проверку списка изменений перед публикацией.

## 3. Отправь файлы в GitHub

Рекомендуемый способ — GitHub Desktop:

1. Склонируй `https://github.com/Mulpee/ChemAnalyzer` на компьютер.
2. Скопируй подготовленную папку проекта в локальную папку репозитория.
3. Убедись, что `README.md` находится в самом корне рядом с `package.json`, а не внутри дополнительной вложенной папки.
4. Открой GitHub Desktop и посмотри список изменений. Убедись, что там нет `.env`, ключей, локальных баз данных или личных файлов.
5. В поле Summary напиши `Prepare ChemAnalyzer 3.2.0 showcase repository`.
6. Нажми **Commit to main**, затем **Push origin**.

Если репозиторий уже содержит созданный при настройке README, его можно заменить новой версией из комплекта.

## 4. Настройки репозитория на GitHub

- Видимость: Public, если ты действительно хочешь показывать исходный код.
- Description: `A Windows desktop application for drawing, analyzing, and exploring small-molecule structures.`
- Сохрани `COPYRIGHT.md` и отсутствие стандартной open-source лицензии: это соответствует выбранному режиму Showcase.
- Не добавляй MIT, Apache-2.0 или GPL лицензию, если не решил сознательно открыть проект на этих условиях.
- Сохрани существующий workflow `build-windows.yml`; он запускает Windows-сборку вручную через Actions или при push тега `v*`.

## 5. Проверка после публикации

1. Открой главную страницу `https://github.com/Mulpee/ChemAnalyzer`.
2. Проверь, что баннер отображается, а ссылки в README открываются.
3. Открой вкладку **Actions** и при необходимости вручную запусти `Build ChemAnalyzer for Windows`.
4. Не объявляй Windows installer готовым к распространению, пока не проверишь `.exe` на чистой Windows-машине по `DESKTOP_BUILD_GUIDE.md`.

## Важное различие

Публичный репозиторий позволяет посетителям просматривать проект, но сам по себе не делает оригинальный код открытым ПО. `COPYRIGHT.md` фиксирует выбранный Showcase-режим; сторонние зависимости и данные всё равно регулируются собственными лицензиями, перечисленными в `LICENSE_NOTICES.md`.
