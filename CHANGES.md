# Версия 3.2.0 — ПК «Антидот-Прогноз»

- Добавлена вкладка `Антидот-Прогноз` с двумя раздельными направлениями: антидотная и рострегулирующая активность.
- Добавлен backend endpoint `POST /api/molecules/specialized-activity`.
- Добавлен общий формат специализированных моделей: отдельные модели по endpoint и контексту опыта, обучение на Morgan fingerprints/RDKit, scaffold-based cross-validation, метрики ROC-AUC, balanced accuracy и MCC.
- Добавлены пустые CSV-шаблоны с обязательной прослеживаемостью источника. Экспериментальные данные не выдумываются и не включены в поставку.
- Если модели отсутствуют, интерфейс показывает «Модель не обучена». Для структур вне области применимости численный прогноз скрывается.
- В UI добавлено предупреждение, что оценка модели не является откалиброванной вероятностью или медицинской/агрономической рекомендацией.

# Версия 3.1.2 — финальная стабилизация ресурсов и идентификации

## Исправлено
- Ketcher static resources копируются из установленного пакета в `frontend/public/ketcher-assets` перед dev- и production-сборкой. При отсутствии исходных ресурсов сборка завершается понятной ошибкой, а не создаёт тихо неполный интерфейс.
- Ketcher получает отдельный URL `/ketcher-assets`, не смешанный с корнем frontend.
- Вкладка идентификации теперь явно показывает название и IUPAC как подтверждённые только при `exact`; совпадение `connectivity` отображается как кандидат.
- Ассистент получает подтверждённое название только при точном совпадении; кандидат по связности передаётся отдельно.
- История и CSV больше не представляют CID/InChIKey совпадения по связности как подтверждённые данные: для кандидатов добавлены отдельные поля CSV.
- `electron-builder` добавлен как зависимость сборки; требования Node.js синхронизированы на `>=24.20.0`.
- Добавлена Windows-сборка через GitHub Actions и локальный скрипт `scripts/build-windows.ps1`.

## Статус выпуска
- Backend-тесты проверяются через `pytest`.
- Тесты Electron запускаются через `npm run test:electron`.
- Полная Windows-сборка и запуск установщика должны быть подтверждены на Windows; исходный архив не содержит готовый `ChemAnalyzer.exe`.

# Версия 3.1.1 — проверка и исправления

Полная проверка приложения: контракт API ↔ схемы ↔ типы, отрисовка всех экранов на
реалистичных данных (включая реальную форму ответов PubChem/ChEMBL), чтение кода.

## Исправлено
- **История и тема пропадали при каждом запуске desktop-приложения**: localStorage
  привязан к origin, а порт backend случайный. Теперь состояние хранится в файлах в папке
  данных (`state\history.json`, `state\theme.json`) через безопасное хранилище Electron
  (белый список ключей, лимит размера, атомарная запись).
- **Совпадение «только по связности» подставляло название вещества в заголовок и историю**
  (противоречило принципу «не называть без подтверждения»). Название — только при точном
  совпадении; при связностном — формула и пометка «по связности возможно: …».
- **Разная стандартизация в разных вкладках**: Drug-likeness, прогноз по сходству и ключи
  для PubChem/ChEMBL не нейтрализовали заряды (ADME — нейтрализовал). Теперь везде одна:
  наибольший фрагмент + нейтрализация. Для солей добавлено предупреждение.
- Вкладки не помещались: «История» и «Ассистент» были скрыты без признаков прокрутки.
  Теперь вкладки переносятся на вторую строку.
- Гонка в 3D: ответ для прежней молекулы мог показаться на вкладке новой.
- Сообщение «сервер недоступен» советовало запустить `uvicorn` даже в установленном
  приложении; теперь текст зависит от режима.
- Типографика истории (старые CSS-правила по позиции элементов).
- Дублирование фраз: «QSAR-модель не обучена…» и два сообщения при пустом ChEMBL; в баннере
  Липински.
- В карточках свойств не было формулы; в строке состояния была зашита устаревшая версия
  (теперь берётся из `package.json`).
- Кнопка «Вставить» в Ketcher: разрешено чтение буфера обмена — только для своего origin.
- `build-backend.ps1` / `run_training.ps1` падали при отсутствии лаунчера `py`.

## Добавлено
- `tests/test_contract.py`: сверка кода backend, схем Pydantic и типов TypeScript
  (проверено мутациями: пропуск обязательного поля и дрейф типов ловятся).
- Тесты хранилища Electron (6), логики истории и темы.

  обрезались, а розовая зона была неправильной формы — исправлено.

# Версия 3.0.0 — desktop-приложение

## Архитектура
- Electron-оболочка (`electron/`): свободный порт -> backend -> health-check ->
  окно; корректная остановка backend (включая дочерние процессы).
- Backend собирается PyInstaller (`chemanalyzer-backend.spec`) вместе с RDKit;
  пользователю Python не нужен. Установщик NSIS и portable (electron-builder).
- Интерфейс раздаёт сам backend (тот же origin): CORS в desktop-режиме отключён,
  проверка Host, backend слушает только 127.0.0.1, документация API выключена.
- Безопасность Electron: contextIsolation, sandbox, без nodeIntegration, CSP,
  белый список внешних URL, проверка IPC, безопасные имена файлов.
- Иконка (`assets/icon.ico`, `icon.png`), скрипты `scripts/`.

## Backend
- PubChem вынесен из `/analyze` в `/identify`: медленный сервис не задерживает
  локальный анализ. Три раздельных уровня (точное / по связности / похожие);
  статусы `found` / `not_found` / `unavailable`; быстрый отказ при отсутствии сети.
- QSAR: статусы `ready` / `not_trained` / `error`, версия модели, честный текст
  «QSAR-модель не обучена».
- `/conformer` принимает `seed` (перестроение 3D), `/depict` отдаёт SVG.
- Модели и `.env` ищутся в папке данных пользователя (`CHEMANALYZER_DATA_DIR`).
- Тесты: pytest (PubChem, QSAR-ядро, безопасность) и `scripts/selftest.py`.

## Интерфейс
- Новый макет: меню File/Edit/Structure/Analysis/View/Settings/Help, панель
  инструментов, редактор слева, 8 вкладок справа, строка состояния.
- Вкладки: Свойства, Идентификация, Drug-likeness (PASS/WARNING/FAIL), Активность,
  ChEMBL, 3D («Построить 3D», «Перестроить»), История, Ассистент.
- Импорт SMILES, примеры, светлая и тёмная темы (CSS-переменные), окно «О программе».
- Экспорт: SMILES, JSON, CSV (защита от формул Excel), SVG, PNG, PDF-отчёт.
- Убран внешний шрифт Google Fonts (приложение работает офлайн, совместимо с CSP).
- Исправлено: граница WARNING (≥ 90% лимита) в коде не совпадала с документацией.

# Версия 2.0.1 — исправления

## Backend
- **PubChem**: SMILES теперь отправляется POST-запросом в теле, а не в пути URL
  (символы `/ \ # +` в пути ломали поиск для многих молекул).
- **PubChem**: обработка ответа 202 (задача в очереди, ListKey) с опросом результата.
- **PubChem**: CID `0` («нет совпадений») больше не считается найденным веществом.
- **PubChem**: запрашиваются только нужные свойства (`IUPACName,Title,InChIKey`) —
  устаревшее имя свойства отклоняло весь запрос.
- **RDKit**: пустая/пробельная строка SMILES даёт понятную ошибку 400.
- **CORS**: разрешён любой порт `localhost` (Vite уходит на 5174+, если 5173 занят).
- Расчёт RDKit вынесен из event loop (`run_in_threadpool`).

## Frontend
- Добавлен `src/vite-env.d.ts`: без него `npm run build` падал на `import.meta.env`.
- Пустой редактор / ошибка `getSmiles()` теперь показывается пользователю
  (раньше — необработанное исключение, без сообщения).
- Индикатор API проверяет реальный `/health` (раньше всегда «online»).
- Понятные сообщения: сервер не запущен, ответ не JSON, ошибки валидации 422
  (раньше выводилось `[object Object]`).
- «Очистить» использует пустой molfile вместо `setMolecule("")`.
- Ошибки загрузки структуры из истории и `localStorage` обрабатываются.
- CSS: убран `min-width: 1180px` у `body`, из-за которого не работали `@media`.
- `@types/react*` перенесены в `devDependencies`.
